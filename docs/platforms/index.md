# Platforms

The WordNet TypeScript ecosystem supports multiple platforms, each optimized for specific use cases and environments.

## Web Applications

Perfect for browser-based applications, interactive demos, and client-side WordNet functionality.

- **React Integration**: Built-in hooks and components
- **Web Workers**: Non-blocking operations
- **OPFS Storage**: Persistent browser storage
- **Cross-Browser**: Works in all modern browsers

**[Get Started with Web →](/platforms/web/)**

## Node.js Applications

Ideal for server-side processing, APIs, and backend services.

- **SQLite Integration**: Local database management
- **File System**: Direct file operations
- **CLI Package**: Command-line utilities
- **High Performance**: Optimized for server environments

**[Get Started with Node.js →](/platforms/node/)**

## Command Line Interface

Perfect for data exploration, scripting, and quick lookups.

- **Interactive TUI**: Terminal user interface
- **Batch Operations**: Process multiple queries
- **Data Management**: Download and manage lexicons
- **Scripting**: Integrate with shell scripts

**[Get Started with CLI →](/packages/wn-cli/tui/)**

## Which Platform Should I Choose?

### **Building a Web App?**
Choose **Web** if you're building:
- Interactive dictionary applications
- Educational tools
- Browser-based demos
- Client-side semantic analysis

### **Building a Server App?**
Choose **Node.js** if you're building:
- REST APIs
- Data processing pipelines
- Server-side semantic analysis
- Backend services

### **Need Command Line Tools?**
Choose **CLI Package** if you need:
- Quick word lookups
- Data exploration
- Batch processing
- Integration with shell scripts

## Cross-Platform Compatibility

All platforms share the same core API, making it easy to:
- Switch between platforms
- Share code between web and Node.js
- Maintain consistent behavior
- Learn once, use everywhere
